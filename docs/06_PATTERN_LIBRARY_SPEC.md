# 06 — Pattern Library Specification

## But
Empêcher la génération arbitraire et transformer des structures éprouvées en briques réutilisables.

## Exemples initiaux
- Manual → Automation
- Problem → Solution
- Before → After
- Mistake → Consequence → Fix
- Contrarian Hook → Explanation
- Show Result First → Explain
- Founder Observation → Lesson
- Live Product Proof

## Champs d'un Pattern
- id
- name
- version
- status
- sourceType
- description
- whenToUse
- audienceFit
- hookStructure
- storyStructure
- visualStructure
- CTAStyle
- exampleAbstracts
- constraints
- knownRisks
- historicalPerformance
- confidence
- createdAt
- updatedAt

## Provenance
Un concept doit pouvoir dire pourquoi il existe :
- INTERNAL_PATTERN
- USER_IDEA
- RESEARCH_PATTERN (plus tard)
- PERFORMANCE_VARIANT (plus tard)

## Règle
Le système peut combiner des patterns, mais doit conserver la provenance et l'hypothèse testée.
